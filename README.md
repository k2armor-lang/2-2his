# 근현대 전시전 기획하기 — 가상 전시 사이트

**근현대 전시전 기획하기** — 1910년 국권 침탈부터 현대까지를 다루는
한국사2 2학기 수행평가용 가상 박물관입니다.

학생은 **전시실 세 곳 가운데 한 곳만 고르고**, 그 전시실을 **고른 이유**를 적은 뒤,
그 시대를 보여 주는 **자료를 세 점까지** 전시합니다. 자료는 유물·문화재든
역사적 사건을 담은 사진이든 같은 형식으로 등록합니다. 다 만들면
**선생님께 제출하기** 버튼 하나로 제출합니다. 표지가 붙은 도록이 `학번_이름.pdf`로
선생님 구글 드라이브 폴더에 바로 저장됩니다(학생 로그인 불필요).
설정 방법은 아래 **선생님께 제출하기 설정**을 보세요.

빌드 도구나 서버가 필요 없는 **순수 정적 사이트**(HTML/CSS/JS)입니다.
`index.html`을 더블클릭해도 열리고, GitHub Pages에 그대로 올려도 동작합니다.

- 모든 경로가 **상대 경로**라 어느 주소에 올려도 그대로 동작합니다.

  연결이 안 되면 기기에 있는 명조·고딕으로 자동 대체됩니다.
- 최상단의 평가계획 `.hwp` · `.pdf` 문서는 `.gitignore`에 들어 있습니다.
  **저장소에 올라가지 않으므로 배포 주소로 공개되지 않습니다.**

## GitHub Pages 배포 방법

### 1단계 — 저장소 만들기

1. GitHub에 로그인하고 오른쪽 위 **＋ → New repository**를 누릅니다.
2. **Repository name**에 이름을 넣습니다. 예: `history-museum`
   (이 이름이 나중에 주소에 들어갑니다. 영문 소문자와 하이픈만 쓰는 편이 안전합니다.)
3. **Public**을 고릅니다. ※ 무료 계정은 Private 저장소로 Pages를 쓸 수 없습니다.
4. **Create repository**를 누릅니다.

### 2단계 — 파일 올리기

이 폴더는 이미 git 저장소입니다. 원격 주소만 연결하면 됩니다.

```bash
git remote add origin https://github.com/<내아이디>/<저장소이름>.git
git push -u origin main
```

웹에서 올린다면 **Add file → Upload files**로 이 폴더 **안의 파일들**을
드래그해 올립니다(폴더 자체가 아니라 안의 내용물). `index.html`이 저장소
최상단에 보여야 정상입니다.

### 3단계 — Pages 활성화

1. 저장소 위쪽 **Settings**(설정) 탭을 누릅니다.
2. 왼쪽 메뉴에서 **Pages**를 누릅니다.
3. **Build and deployment** 항목에서
   - **Source**: `Deploy from a branch`
   - **Branch**: `main` / 폴더는 `/ (root)`
4. **Save**를 누릅니다.

### 4단계 — 주소 확인

저장 후 1~2분 기다렸다가 **Settings → Pages** 화면을 새로고침하면
맨 위에 `Your site is live at ...` 초록색 안내와 주소가 나타납니다.

```
https://<내아이디>.github.io/<저장소이름>/
```

### 잘 안 될 때

| 증상 | 확인할 것 |
|---|---|
| 404 페이지가 뜬다 | `index.html`이 저장소 **최상단**에 있는지. `assets` 폴더 안에 들어가 있으면 안 됩니다. |
| 글자만 나오고 디자인이 깨진다 | `assets/css/style.css`가 함께 올라갔는지. 폴더 구조가 유지되어야 합니다. |
| 수정했는데 그대로다 | 배포에 1~2분 걸립니다. 그래도 그대로면 브라우저 새로고침(Ctrl+Shift+R). |
| 주소가 아예 안 보인다 | 저장소가 Private이면 무료 계정에서는 Pages가 켜지지 않습니다. Public으로 바꾸세요. |

### 배포 후 꼭 알아둘 점

**주소가 바뀌면 학생이 작성한 내용은 따라오지 않습니다.** 저장 위치가 브라우저의
사이트별 저장소(localStorage)라 `file://`로 열었을 때와 `github.io`로 열었을 때가
서로 다른 공간입니다. 배포한 뒤에는 **처음부터 배포 주소로만** 작업하게 하세요.

## 선생님께 제출하기 설정

학생이 **선생님께 제출하기**를 누르면 사이트가 글과 사진을 Google Apps Script 웹 앱으로
보내고, 웹 앱이 도록 PDF를 만들어 선생님 드라이브 폴더에 저장합니다.
학생은 구글에 로그인하지 않으므로 아이패드의 Gmail·구글 로그인 제한과 상관없이 동작합니다.

### 1단계 — Apps Script 만들기 (한 번만)

1. 제출을 받을 구글 계정으로 [script.google.com](https://script.google.com)에 들어가
   **새 프로젝트**를 만듭니다. 이름은 예: `전시전 제출 받기`
2. 기본으로 들어 있는 코드를 모두 지우고 `apps-script/Code.gs` 내용을 통째로 붙여 넣습니다.
3. 맨 위 `FOLDER_URL`에 받을 드라이브 폴더 주소가 들어 있는지 확인합니다.
   (지금은 `2학기 한국사2 수행평가 - 근현대 전시전 기획하기` 폴더로 되어 있습니다.)
   비워 두면 내 드라이브에 같은 이름의 폴더를 새로 만듭니다.
   ※ 이 계정이 그 폴더에 **편집 권한**을 가지고 있어야 합니다.
4. 저장 → 위쪽 함수 목록에서 `setup`을 고르고 **실행**을 누릅니다.
   권한 요청 창이 뜨면 계정을 고르고 **고급 → (안전하지 않음)으로 이동 → 허용**을 누릅니다.
   (직접 만든 스크립트라 구글 검토를 받지 않았다는 뜻입니다.)
   실행이 끝나면 폴더 안에 `제출 명단` 시트가 생깁니다.

### 2단계 — 웹 앱으로 배포

1. 오른쪽 위 **배포 → 새 배포** → 톱니바퀴에서 **웹 앱**을 고릅니다.
2. 다음처럼 설정하고 **배포**를 누릅니다.
   - **다음 사용자 인증 정보로 실행**: `나`
   - **액세스 권한이 있는 사용자**: `모든 사용자` ← 반드시 이것 (학생이 로그인하지 않으므로)
3. 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사합니다.
   브라우저에서 이 주소를 열어 `{"ok":true,"service":"museum-submit"}`이 보이면 정상입니다.

> 학교(Google Workspace) 계정은 관리자 설정 때문에 `모든 사용자`가 목록에 없을 수 있습니다.
> 그때는 개인 Gmail 계정으로 1~2단계를 다시 하고, 받는 폴더를 그 계정에 편집 권한으로 공유하세요.

### 3단계 — 사이트에 주소 넣기

`assets/js/submit-config.js`의 따옴표 안에 웹 앱 URL을 붙여 넣고 GitHub에 올립니다.

```js
window.MUSEUM_SUBMIT_URL = 'https://script.google.com/macros/s/……/exec';
```

### 제출되면 생기는 것

| 위치 | 내용 |
|---|---|
| 받는 폴더 | `학번_이름.pdf` — 표지·선택 이유·자료별 사진과 설명. 다시 내면 지난 파일은 휴지통으로(30일 내 복구 가능) |
| `제출 명단` 시트 | 제출 시각 · 학번 · 이름 · 전시실 · 자료 수 · 사진 수 · 제출 횟수 · PDF 링크 (다시 낼 때마다 한 줄씩 추가) |

### 기기 보관본 (다시 제출용)

제출을 누를 때마다 보낸 내용 전체가 **그 아이패드의 브라우저 보관함(IndexedDB)**에
학번_이름별로 저장됩니다. 작성 중인 내용과 달리 **로그아웃하거나 전시실을 바꿔도 지워지지 않습니다.**
나중에 파일이 잘못되었거나 제출이 실패했다면, 같은 기기에서 같은 학번·이름으로 들어와
로비 제출 칸의 **기기에 보관된 제출본 다시 보내기**를 누르면 그때 내용 그대로 다시 제출됩니다.

※ Safari의 방문 기록·웹 사이트 데이터 지우기, 비공개 브라우징에서는 보관본도 사라집니다.

### 코드를 고쳤다면

`Code.gs`를 수정한 뒤에는 **배포 → 배포 관리 → 편집 → 버전: 새 버전 → 배포**를 해야 반영됩니다.
이렇게 하면 웹 앱 URL은 그대로 유지됩니다. (‘새 배포’를 하면 주소가 바뀝니다.)

## 사이트 기능

### 입장 화면 (학번·이름)

처음 들어가면 학번·이름 입력 화면이 먼저 뜨고, 입력 전에는 본문이 보이지 않습니다.
주소창에 `index.html#room2`처럼 특정 전시실을 직접 쳐서 들어가도 똑같이 막힙니다.
입장 후에는 화면 위쪽에 `기획자 11101 · 홍길동`이 표시되고,
옆의 **학번·이름 수정** 버튼으로 언제든 고칠 수 있습니다(작성 내용은 그대로 유지).

**입력과 동시에 페이지 제목이 `학번_이름`(예: `11101_홍길동`)으로 바뀝니다.**
브라우저는 PDF로 저장할 때 페이지 제목을 파일 이름으로 쓰기 때문에,
아이패드에서 *공유 → 파일에 저장*을 눌러도 `11101_홍길동.pdf`로 채워집니다.

표시줄의 **로그아웃**은 학번·이름과 작성한 내용(`museum-` 으로 시작하는 저장값)을
모두 지우고 처음 입력 화면으로 되돌립니다. 되돌릴 수 없으므로 누르면 한 번 물어봅니다.
공용 아이패드를 여러 학생이 돌려 쓸 때 쓰면 됩니다.

> 과제용 화면 가리개이지 보안 장치가 아닙니다. 브라우저 저장소를 지우거나
> 자바스크립트를 끄면 열립니다. 민감한 개인정보는 넣지 마세요.

### 화면 구성

`index.html` 하나에 모든 것이 들어 있지만, 화면은 네 개로 나뉩니다.
`main.js`가 주소의 `#`을 보고 한 번에 하나만 보여 줍니다.

```
로비(#lobby) ─ 히어로 · 이렇게 기획합니다 · 전시실 고르기(#rooms) · 제출하기(#export)
   │  카드를 눌러 한 곳을 고르면
   └─→ 고른 전시실 하나(#room1 · #room2 · #room3)
        선택 이유 + 자료 카드(최대 3장) + PDF 저장
```

- 고르지 않은 전시실 주소(`#room1` 등)로 직접 들어가려 하면 로비의
  **전시실 고르기** 구획으로 되돌려 보냅니다.
- 브라우저 뒤로 가기도 그대로 동작합니다(주소의 `#`만 바뀌는 구조).
- 자바스크립트가 없으면 화면을 나누지 않고 전부 이어서 보여 줍니다.

### 전시실 고르기 — 한 곳만

로비의 전시실 카드 세 장은 처음에 모두 `미선택` 상태입니다.
**하나를 누르는 순간 그 전시실로 확정**되고, 나머지 두 장은 `선택 안 함`으로
잠겨 눌리지 않습니다. 고른 카드의 배지는 작성 진행도를 보여 줍니다.

| 배지 | 뜻 |
|---|---|
| `미선택` | 아직 아무 곳도 고르지 않음 (세 장 모두 고를 수 있음) |
| `선택 안 함` | 다른 전시실을 골라 잠긴 카드 |
| `아직 비어 있음` | 내 전시실이지만 선택 이유·자료가 모두 비어 있음 |
| `작성 중` | 선택 이유나 자료 가운데 일부만 채워짐 |
| `작성 완료 ✓` | 선택 이유 + 자료 세 점(사진·설명·배경)이 모두 채워짐 |

전시실 고르기 제목 옆의 **다른 전시실로 바꾸기**를 누르면 다시 고를 수 있습니다.
다만 **그 전시실에 쓴 선택 이유와 자료가 모두 지워지므로** 한 번 물어봅니다.

### 선택 이유

전시실 화면 맨 위에 `이 전시실을 선택한 이유` 칸이 있습니다.
글자 수 제한이 없고 자동으로 높이가 늘어나며, 입력 뒤 잠깐 있다가 저장됩니다.
이 글은 도록 PDF **표지**에도 함께 실립니다.

### 전시 자료 카드

전시실 하나에 **자료를 최대 세 점**까지 놓습니다.
처음에는 빈 카드가 한 장 놓여 있고, **＋ 자료 등록**으로 늘립니다
(세 장을 채우면 버튼이 저절로 숨습니다).

| 구성 | 하는 일 |
|---|---|
| 카드 머리글 | `EXHIBIT 01` 줄을 누르면 카드를 접었다 펼 수 있습니다(접어도 머리글은 보임) |
| 사진 첨부 | 액자 안쪽을 눌러 파일 선택, 또는 이미지를 끌어다 놓기. 누르면 교체, ‘사진 삭제’로 비움 |
| 자료 설명 | 유물이라면 이름·시기·쓰임새, 사건 사진이라면 언제·어디서 찍은 장면인지 |
| 역사적 배경과 의미 | 어떤 사건과 이어지고 그 속에서 어떤 의미를 갖는지 |
| 카드 삭제 | 오른쪽 위 **×** (확인 후 삭제, 자리가 비면 ＋ 버튼이 다시 나타납니다) |

서술칸은 글자 수 제한이 없고, 줄이 늘어나면 칸 높이가 자동으로 늘어납니다.
유물이든 사건 사진이든 **같은 형식 하나로 등록**합니다
(예전에는 자료 종류를 먼저 고르게 했지만 학생들이 헷갈려 해서 합쳤습니다).

전시 점수를 바꾸려면 `assets/js/exhibit.js` 위쪽 두 값을 고칩니다.

```js
var DEFAULT_CARDS = 1;   // 처음 놓이는 빈 카드 수
var MAX_CARDS = 3;       // 한 전시실에 전시할 수 있는 자료 수
```

### 자동 저장

입력한 글과 사진은 브라우저 저장소에 자동 저장됩니다.
사진은 가로세로 최대 1200px, JPEG 품질 0.8로 축소해 보관합니다.

**저장 공간이 모자랄 때**(브라우저마다 5MB 안팎):

1. 900px · 품질 0.6으로 **한 번 더 줄여** 다시 저장해 봅니다.
2. 그래도 들어가지 않으면 **사진을 넣기 전으로 되돌리고** 빨간 글씨로 알립니다.

화면에 보이는 사진은 반드시 저장까지 끝난 사진입니다.
(예전에는 저장에 실패해도 사진이 화면에 남아, 새로고침하면 사라졌습니다.)

- 다른 기기·다른 브라우저에서는 보이지 않습니다.
- 인터넷 사용 기록·사이트 데이터를 지우면 함께 지워집니다.
- 시크릿 모드에서는 저장되지 않습니다.

#### 저장되는 값

| 키 | 내용 |
|---|---|
| `museum-visitor` | `{"sid":"11101","name":"홍길동"}` |
| `museum-room-choice` | `{"room":"room2","reason":"고른 이유…"}` |
| `museum-exhibit:room2` | `[{"photo":"data:image/jpeg;base64,…","desc":"…","event":"…"}, …]` |

자료 카드는 배열 순서가 곧 화면 순서입니다.
`museum-exhibit:` 키는 **고른 전시실 것만** 만들어집니다.

### 전시 도록 PDF

**PDF로 저장** 버튼은 ① 화면 맨 위 기획자 표시줄, ② 전시실 아래쪽,
③ 로비의 ‘제출하기’ 칸 — 세 곳에 있습니다. 어느 버튼이든, 지금 어느 화면을
보고 있든 **학생이 고른 전시실 하나**를 모읍니다. 누르면 표지(제목·기획자·과목·
작성일·전시실·선택 이유)와 자료 카드가 담긴 인쇄 창이 열립니다.
프린터를 고르는 칸에서 **‘PDF로 저장’**을 선택하면 됩니다.

- 파일 이름은 **`학번_이름.pdf`**로 미리 채워집니다.
  (인쇄 직전에 문서 제목을 학번_이름으로 바꿔 두는 방식입니다.
  브라우저 정책상 저장 위치까지 자동으로 정할 수는 없어, 저장창은 직접 눌러야 합니다.)
- 아이패드 사파리는 인쇄 창 → 오른쪽 위 **공유 → 파일에 저장** 순서로 저장합니다.
- 사진·글이 모두 빈 카드는 도록에서 빠집니다. 사진만 없으면 ‘사진 없음’으로 들어갑니다.
- 자료 카드는 페이지 중간에서 잘리지 않고 카드 단위로 넘어갑니다(A4 세로 기준).
- 그림이 안 나오면 인쇄 설정에서 **‘배경 그래픽’**을 켜 주세요.
- 버튼 대신 브라우저 인쇄(Ctrl+P · 공유▸프린트)를 눌러도 같은 도록이 나옵니다.
  (`beforeprint` 시점에 도록 문서를 대신 만들어 둡니다.)

**저장할 수 없을 때의 안내**(학번·이름 없음 / 전시실 미선택 / 등록된 자료 없음)는
지금 보고 있는 화면의 안내 자리에 뜨고, 방금 누른 버튼 글자로도 잠깐 바뀌어
어느 화면에서 눌러도 결과를 알 수 있습니다.

## 디자인 바꾸기

화면은 밝은 종이색 바탕과 전시 포스터, 전시실별 녹색·주홍색·청회색 포인트로 구성됩니다.

- 화면용 색과 전시실 테마는 `assets/css/museum.css`에서 관리합니다. `style.css`의 기본 어두운 색 토큰은 공통 기본값이며, 화면에서는 `.museum`과 `.theme-room1/2/3`가 덮어씁니다.
- 화면 디자인 규칙은 `index.html`에서 `style.css` → `museum.css` → `tablet.css` 순서로 불러옵니다. `tablet.css`는 화면용 태블릿 배치와 터치 크기를 보정합니다.
- PDF 인쇄 스타일은 `style.css`에 있으므로 화면 전용 변경과 구분해 확인하세요.
- 색을 고를 때는 실제 종이색·포스터 배경 위에서 본문과 조작 요소의 글자 대비를 확인하세요.

## 반응형 기준

태블릿 배치는 화면 폭으로 정하고, 터치 보정은 `any-pointer: coarse` 조건으로 적용합니다. 메뉴는 폭 900px 이하에서 접힙니다.

| 화면 폭 | 로비 전시실 카드 | 작성 화면 자료 카드 | 상단 메뉴 |
|---|---|---|---|
| 1367px 이상 | 3열 | 카드 안 사진·설명 1열 | 가로 메뉴 |
| 960–1366px | 3열 | 카드 안 사진·설명 2열 | 가로 메뉴 |
| 901–959px | 포스터 옆에 상태·제목·설명을 둔 1열 | 카드 안 사진·설명 1열 | 가로 메뉴 |
| 701–900px | 포스터 옆에 상태·제목·설명을 둔 1열 | 카드 안 사진·설명 1열 | 접이식 메뉴 |
| 700px 이하 | 세로형 1열 | 카드 안 사진·설명 1열 | 접이식 메뉴 |

자료 카드 목록은 1열입니다. 폭 960–1366px에서는 각 카드 안에서 사진과 설명을 나란히 배치합니다. 터치 포인터에서는 주요 조작 영역을 최소 44px, 입력 글자를 17px로 보정합니다.

## 개발 메모

정적 파일이라 `index.html`을 더블클릭해도 열리지만,
브라우저 확장·자동화 도구로 확인할 때는 로컬 서버가 편합니다.

```bash
python -m http.server 8777 --bind 127.0.0.1
# http://127.0.0.1:8777/index.html
# http://127.0.0.1:8777/test/ipad-preview.html   ← 아이패드 크기로 미리보기
```

`test/ipad-preview.html`은 기종(iPad · Air · Pro · mini)과 가로/세로를 골라
실제 뷰포트 크기 그대로 `index.html`을 띄워 봅니다.
**JS·CSS를 고친 뒤에는 캐시 때문에 옛 파일이 그대로 도는 일이 있으니
Ctrl+Shift+R로 강제 새로고침해서 확인하세요.**
